## 项目是什么

《下次做给我吃》是一部六集、9:16 的 AI 有声竖屏短剧。起点是一条没有完整对白的母女早餐广告；我们重新设计了独立剧情：女儿知遥离职后接下早餐店拍摄工作，在名单中发现妈妈丽珍的店要转让。她以为妈妈缺钱，后来才知道妈妈打算把店交给徒弟阿禾，自己去看海。母女最终分别说出隐瞒的事，重新约定下一顿早餐。

六集成片合计约 **403 秒**，交付物还包括正片前预热片和独立宣传片。项目采用 Musein 生成候选镜头，通过本地脚本完成镜头裁切、声源管理、文字合成和整集导出。本仓库公开项目复盘、制作 SOP、渲染代码与成本核算，供创作者和 AI 产品团队复用。

## 制作流程与技术架构

![短剧镜头生产与验收流水线](images/production-pipeline.svg)

制作流程围绕镜头展开：剧本确定人物目标与对白，角色参考图约束外观，生成平台产出候选素材，JSON 清单记录采用秒段和声源，FFmpeg 负责合成，人工审片确认人物、口型与叙事连续性。复盘后的 SOP 将双人对话小样前置，在批量生成前验证声线、表演和口型。

| 环节 | 实现方式 | 输出 |
|---|---|---|
| 角色与分镜 | 固定角色参考图；记录服装、场景及道具起止状态；逐镜指定说话人和准确台词 | 角色参考与镜头再生清单 |
| 素材选择 | 保存历史候选，按源视频时间码选择可用区间 | 可回退的镜头版本 |
| 时间线 | JSON manifest 配置源片、入出点、裁切区域、原声模式及画外声入点 | [镜头清单示例](examples/episode-demo.json) |
| 音视频合成 | FFmpeg 同区间裁切音画，统一 720×1280、24 fps、48 kHz；响度标准化和峰值限制 | H.264/AAC 竖屏成片 |
| 技术质检 | 校验媒体流、总时长与画幅，完整解码，检查内部切点附近黑帧 | 导出检查结果 |
| 内容验收 | 静音看、闭眼听、带声逐镜、六集连看 | 精确到镜头和时间码的修复清单 |

渲染器与字段说明见 [技术实现](docs/technical-implementation.md)，新项目执行步骤见 [制作 SOP](docs/production-sop.md)。

## 真实故障与技术修复

| 故障 | 定位依据 | 实际修复 |
|---|---|---|
| 双手机、早餐状态跳变 | 逐帧核对接电话动作；检查蛋、吐司和餐盘的数量与位置 | 重生单手机镜头；第一集采用新源片 0–8 秒，裁掉后续蛋与吐司分离的异常尾段；相邻镜头尽量取同一源片连续区间 |
| 第五集女儿的问句落在妈妈嘴上 | 将“你真去啊”的音频区间与可见说话人逐句对照 | 换成女儿露脸的新镜头，采用源片 2.8–7.2 秒及其同期声；停用旧画外 WAV，妈妈只保留不露嘴的肩部前景 |
| 第六集机器声与原声重叠 | 独听各声轨，再核对 manifest 中启用的叠加音频 | 将问题 WAV 的 `enabled` 设为 `false`，纸条镜头设为 `source_audio: mute`，保留后续合格同期对白 |
| 手机名单乱码 | 名单是推动剧情的证据，生成汉字无法稳定读出 | Pillow 绘制名单 UI，利用四角关键帧插值及透视变换贴回屏幕；用肤色遮罩与边缘羽化保留前景手指 |
| 重字与剪辑卡顿 | 对照台词、源片时间码和前后动作状态，定位异常起音及多余反应段 | 同时裁切音画；第二集在问句结束约 0.35 秒后切入解围裙动作，删去重复音节和冗余反应；统一帧率后重新导出 |
| 六集目标不清楚 | 连看后无法解释女儿为何拍店、妈妈为何转店 | 梳理人物目标与六集因果链，补充预热片交代背景；将陌生观众的理解测试纳入后续验证 |

## 怎么验收

1. **静音看**：人物是否一眼能认出；空间方向、站姿、道具数量、动作是否连续；关键文字是否可读。
2. **闭眼听**：谁在说话、是否回应上一句、语气是否自然；有没有漏字、重字、双层人声。
3. **带声逐镜看**：可见嘴和声音是否对应；电话是否先接听再传来远端声音；切点是否流畅。
4. **六集连看**：每集人物的选择是否推出下一集的问题；终章是否收束；不靠宣传物料才能看懂核心剧情。

![第六集逐段审片表：人物、空间、纸条和结尾动作连续性](images/episode-06-audit.jpg)

技术检查包括解码、黑帧、时长与声轨；它不能代替人眼人耳判断演技、口型和故事是否成立。

## 成本与效率

制作期共消耗 **11,460 积分**，覆盖候选生成、重拍和两条辅助视频的制作。按同等积分额度估算，**生成资源预算约 530 元**。估算采用 7,200 积分/329 元与 4,300 积分/199 元的套餐组合，合计 11,500 积分/528 元；实际使用部分折合约 526 元。

| 指标 | 结果 |
|---|---:|
| 视频生成 | 124 笔，11,378 积分 |
| 平台 AI 生成 | 10 笔，82 积分 |
| 六集正片时长 | 403 秒 |
| 生成资源预算 | 约 530 元 |

项目使用了活动积分和团队转入积分，现金支出需结合购买凭证核算。上述预算包含抽卡与返工消耗；由于平台流水缺少镜头 ID，暂时无法可靠拆分每集成本和返工占比。Token 处理量及其缓存构成单独列在 [成本核算](docs/cost-accounting.md)，人民币预算以积分账单为依据。

![制作期积分构成与采购估算](images/cost-breakdown.svg)

本项目已完成六集本地成片及两条辅助视频。没有发布后的完播、追更或留存数据，不能把制作完成写成市场验证成功。下一步应让未参与制作的人盲看六集，记录理解断点，再测试首集修改和预热片的实际效果。
