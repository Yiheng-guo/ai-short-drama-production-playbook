# 有声竖屏短剧制作 SOP

## 项目启动

| 项目 | 开工前需要确定 |
|---|---|
| 用户与场景 | 谁会在什么平台、什么时刻看；是否从第一集开始；是否需要静音字幕版。 |
| 产品目标 | 首集能否讲清人物与冲突；每集是否有继续观看的理由；最终希望验证完播、追更、分享还是品牌认知。 |
| 内容边界 | 题材、集数、每集时长、画幅、对白语言、目标平台的内容与音乐版权要求。 |
| 资源约束 | 截止时间、可用积分及到期批次、现金预算、人力工时、设备、可用模型。 |
| 验收人与数据 | 谁定剧本、谁验镜头、谁验声音、谁核交付；记录版本、扣点、重试和问题。 |

《下次做给我吃》从参赛广告的母女早餐关系出发，独立开发六集故事。制作初期先铺多集，后续出现故事不易理解、人物和声画连续性问题；因此本流程把小样和分阶段验收放在大批量生成之前。

## 制作原则

1. **先确定故事和准确台词，再生成镜头。** 先生成几十条视频再硬拼，人物、时间和声画很难救。
2. **每条生成视频都叫候选。** 只有经过视觉、声音、口型、衔接四项核查，才进剪辑时间线。
3. **正面开口优先用同镜同期声。** 后配只用于电话、语音播放、背影、手部和明确的画外声。字幕不承担修复口型的任务。
4. **机器检查和人工看片各管一半。** 解码、黑帧、转写能发现技术或字句线索；演技、声线、口型和故事体验必须人看人听。

## 文件和小样

建文件夹：`script/`（故事、对白）、`refs/`（人物/场景主参考）、`raw/`（下载原片）、`audio/`（角色参考声与候选）、`manifests/`（镜头剪辑表）、`review/`（截图、问题清单）、`output/`（成片）。**原片不覆盖、试片不叫终稿。**每个素材名至少含 `集-镜头-版本`，例如 `E2-04-history2.mp4`。留一张来源表，记平台项目、生成参数、参考图、生成时间、扣点、文件路径和是否通过。

先做一段 **20–30 秒小样**：同一角色、同一场景、两句对话、一个动作接点。这能在大批量耗积分之前暴露换脸、机器声、口型和乱码。小样通过后再批量排产；不通过时先改镜头设计、参考图或声音方案，记录每次尝试的扣点。

## 关卡 1：一句话故事和每集的观看理由

**做法**：先写“主角想要什么—误以为是什么—真正发生了什么—最终做了什么”。再为每集填一行：`主角目标｜眼前阻力｜可见选择｜本集结果｜集尾新问题`。钩子必须由本集发生的事件推出，不能只加一行“下集更精彩”。第 6 集这类终章可以收束，不必硬造第 7 集。

**产出**：一页总故事、逐集卡、人物关系图。**通过标准**：没看过前情的人，能在 30 秒内说出每集谁要做什么；连看六集不需要大字卡补漏掉的行动。

**这次的坑**：初版“女儿为何拍妈妈的店”“妈妈为何转店”“阿禾为何接班”连接不够；旧台词的“七天后/明早出发”相互打架。**处理**：重写为周四发现、周五拍摄/坦白、周六交店、周日下午出发；前置预热片只帮观众进入故事，不代替正片因果。

## 关卡 2：写可拍、可说、可接的剧本

每场写六项：`时间地点｜人物此刻想做的事｜正在做的动作｜准确可听台词｜对方反应｜离开场景的结果`。对白先朗读：人物会这样说吗？她是在回应上一句，还是在念给观众听？有无自然停顿、打断、吸气？删去不能推进动作或关系的说明性台词。

**产出**：锁定的逐集剧本、逐句对白表。**通过标准**：闭眼只听对白也能辨清谁在说、在回应谁；关键情节有行动证据。**退回条件**：人物动机靠旁白解释、同一信息重复讲、时间线矛盾、结尾悬念与下一集无因果。

**这次的坑**：参赛片没有完整对话，初版短剧曾靠画面文字承接；后来机器配音又显得像念稿。**处理**：把电话、面对面争论、阿禾接锅写成真实互动；争执和坦白保留现场声与听者反应。

## 关卡 3：建立“角色、场景、道具、时间”圣经

1. **角色卡**：每人一张已确认的正面主参考图，标年龄感、脸部特征、发型、固定服装和一段通过试听的声线。辅助图只补体态或衣服，不可覆盖主脸。生成工具中**真的上传/绑定图片**。
2. **场景卡**：画简单平面图，标门、窗、柜台、灶、桌子、灯。一个地点只用一组固定参考。
3. **道具账本**：按场景列手机、鸡蛋、盘、饭盒、围裙、车票、纸条的数量、持有人、进出镜状态。例如 `E1：一部白银手机；一片吐司上一枚蛋`。
4. **时间表**：列故事内日期和时段，写明每集与上一集隔多久；检查对白中的“明天、后天、下午两点”。

**产出**：角色/场景圣经 + 道具状态表 + 故事时间轴。**通过标准**：遮住字幕，仍能认出主角；连续场景里道具没有凭空增加、消失或易主。

**这次的坑**：换脸、男厨师、换店、双手机、围裙脱掉后又穿回、餐具从白盘叉子变成空碗筷子。**处理**：固定三位角色图及店/公寓布局；对旧素材只取不露错脸的手、锅等安全秒段，不可为了凑时长硬留危险尾段。

## 关卡 4：把场景拆成“可验收的单镜”

每镜先写一张镜头卡：

```text
编号：E__-__；故事时间/地点：____；时长目标：____秒
参考图：人物____，场景____（已在生成工具中实际绑定）
镜头内动作：起始状态____ → 动作____ → 结束状态____
准确对白与发声者：____；声音类型：同期/电话/语音/画外/无对白
嘴部：谁可见、谁闭嘴、哪句必须同步
道具数量和位置：____；画面里需要读清的字：____
上一镜接点：____；下一镜接点：____；禁止出现：____
```

**生成顺序**：先做角色最容易漂移的对话镜和剧情证据镜，再做锅、手、街道等插入镜。一次只生成少量候选，验过再扩大。新手不要把三个人、四句对白和多个道具都塞进同一条短视频；拆成说话者近景、听者反应、关键动作三镜更容易控制。

**通过标准**：生成源片完整回放后，能逐项勾上镜头卡；若口型、说话人、人物身份或关键动作不成立，直接重生或改镜头设计。

## 关卡 5：先处理最难的声音与口型

**制作次序**：

1. 同一角色选一段能明确归属、干净、带情绪变化的参考声；试听至少一轮完整对话，不能只凭一句平静短句锁声线。不要把另一角色或电话远端混入参考。
2. 每场尽量生成/录制连续表演，带停顿和环境声，再切句。建立对白表，给每句标入点、说话人、情绪和声源距离。
3. 正面露嘴时，用原片里准确自然的同期声，或用最终音频驱动嘴型。工具不能做到，就把镜头改成侧背面、手部或听者反应。**不要把新声强贴到随机张嘴的正脸。**
4. 电话先拍“来电→接听”，电话音经过听筒质感处理后再入；微信语音先有播放动作。房间内人声、店内人声、电话声分开。
5. 保留锅、门、饭盒等现场声，音乐在人物争执/坦白/犹豫时让位。每完成一场，就纯音频听一遍，再带画面逐句看口型。

**通过标准**：同一人跨集一听能辨；台词不漏字不重字；画内人物开口与正确声源对应；人声不叠两层。**这次的坑**：机械妈妈声、女儿“你真去啊”错给妈妈嘴型、“饿着自自己”、“是这……这边我来”、纸条句机器声与原声重叠。**处理**：优先保留通过试听的同镜同期声；必要时**视频和音轨按同一区间一起剪**；不合格配音直接停用，而非靠字幕补。

本项目试过 Edge TTS、F5-TTS、Qwen3-TTS，并用 faster-whisper 辅助识别。工具结果必须经过试听和口型核验；模型通过一次测试不代表全部角色与情绪都可用。

## 关卡 6：生成文字与画面动作分离

**规则**：名单、交接单、车票、纸条、手机消息这类剧情证据，尽量在生成镜头中留一块平整纸面/屏幕，清楚的字由后期可控图层制作。真实对白必须能独立讲清核心事实，不要让观众靠一秒钟的乱码票面猜剧情。

**这次的坑**：第 2 集“二十多年”字幕乱码，第 3 集离职证明错字，第 6 集纸条伪字。**处理**：近裁/移出错字，必要时补镜；字幕来自最终音频，剧情物件文字另做排版。**通过标准**：原速手机端看得清该读的字，读不清的字不会承担唯一叙事功能。

## 关卡 7：建剪辑清单，再出工作版

镜头清单至少写：`源文件｜源起止秒｜目标顺序｜裁切区域｜保留/静音原声｜补声文件和入点｜前后接动作｜版本号`。按**画面动作和对白气口**切，不按“生成视频恰好 13 秒”切。原片的有效段可能只有 1–8 秒；后半段多手机或道具跳变就舍弃。切掉重复字时音画一起切，避免口型残留。每次修改另存候选版；一集通过再锁版，宣传片只从已锁版本取镜。

**本项目例子**：用 JSON manifest + FFmpeg 渲染 720×1280/24fps；短镜裁切、画外 WAV、电话滤波和混音由清单控制。脚本可以复用，但必须用源片和人工审片验证，不能把“脚本运行成功”当成“短剧可看”。

## 关卡 8：三遍审片 + 一次六集连看

| 审法 | 必看内容 | 常见返工 |
|---|---|---|
| **静音看** | 人物能否一眼认出；场景方向、衣服、道具数、手与锅的动作是否连续；有没有乱码、假文字、突变。 | 换脸/换店/双手机/纸条伪字 → 重生、裁安全片段或后期替换。 |
| **闭眼听** | 声线、人味、停顿、人物回应关系、两层声音重叠、电话质感、音乐是否盖词。 | 机械句/重复字/错声源 → 重录或停用，重新配动作。 |
| **带声逐镜** | 每句由谁开口，起音和收尾是否对上；接听后才听到电话；镜头切点是否卡顿。 | 错口型/掉帧感 → 换同期镜、调切点，音画同删。 |
| **六集连看** | 时间和人物关系有没有回退；每集钩子能否接下一集；终章是否收束。 | 因果缺口 → 补行动/对白镜，不靠一张解释字卡糊过去。 |

再做**技术检查**：媒体信息、完整解码、音视频长度、黑帧/冻结、声轨是否缺失；ASR 只定位疑似漏字/重字。安静处 ASR 会产生假台词，必须截短段和人耳复核。记录问题时写 `集数 + 成片时间 + 源镜头 + 发现 + 处理 + 复验结果`，例如本项目 E5 结尾的说话人错配和 E6 的重叠机器声。

**通过标准**：没有已知明显穿帮，关键对白与可见嘴对应，故事可理解，整片能播放。不要承诺“百分之百没有瑕疵”；未复听/未复看的项明确保留在交付说明。

## 关卡 9：预热、宣传和交付分开做

- **正片前预热片**：给第一次看的观众最低限度背景——人物是谁、女儿为何接拍摄、妈妈的店为何与名单相关；不泄露全部答案。
- **独立宣传片**：卖核心冲突、人物关系和一个强悬念，供单独传播；不承担完整背景教学。
- 两片从锁定正片取镜和同期声。不得因为正片没讲清而只靠宣传物料补剧情。
- 交付表列每集标题、时长、分辨率、文件路径、版号、已做的检查和未解决的细节。发送或上传后**查看接收端/远端实际版本**。本项目参赛片曾遇“提交成功”却仍是旧文件；短剧微信发送后也未能核实全部上传完成，二者都说明“点击发送”不等于“交付完成”。

## 成本与排期管理

开工前从平台页面记录每种生成档位的当时预扣价、有效期、退款规则；按“必需剧情镜、高风险对话镜重试、插入镜、应急补镜”设上限。成本表同时记现金付款和活动赠分，不能把余额当花费。每次生成至少登记：镜头编号、模型与参数、生成时间、扣点、是否退款、失败原因、保留的有效秒数、素材路径、负责人。每集锁版后再汇总一次通过率、每条通过镜头平均扣点和返工占比。

项目排期至少留出故事小样、批量生成、声音修复、整集审片、跨集连看和上传复核。若生成一条 13 秒原片仅 2 秒能用，应先检查镜头卡是否包含过多人物、道具或对白，再决定是否重试。本项目后来补齐个人积分流水，核得制作期 **11,460 分**；[成本核算](cost-accounting.md)示范了如何用余额勾稽，并分开现金、积分、Token 与人力。具体的 [JSON 镜头清单和渲染器](technical-implementation.md)也已公开。

## 发布与效果验证

锁版后做一次未看剧本的观众测试。至少记录：是否能认出三位主角，能否解释女儿接拍、妈妈转店和阿禾接店的关系，看完每集是否知道下集要追什么，以及在哪个时间点退出或困惑。若首次观看必须靠预热片解释核心行动，应回改第一集。发布后再以播放、前 3 秒停留、完播、下一集点击和评论中的剧情误解验证产品假设；没有数据时只写“已交付”，不写“已验证传播效果”。

## 交付检查

- [ ] 六集各有目标、阻力、选择、结果；第 1–5 集有因果钩子，第 6 集收束。
- [ ] 三位主角的主参考图、声线、服装固定；每个生成节点真实绑定对应参考。
- [ ] 店、公寓、便利店的方位与时间轴一致；手机、蛋、餐具、围裙、票、纸有状态账本。
- [ ] 每句对白有发声者、声源和嘴部规则；可见嘴不用错位后配声。
- [ ] 剧情证据字可读，乱码不进入最终画面；字幕与最终人声一致。
- [ ] 每镜完整回放，按人/声/口/连四格验收；失败镜返工后重新勾选。
- [ ] 静音、纯音频、带声、六集连看均完成；技术检查通过且不代替人工验收。
- [ ] 预热片、宣传片用途分开；交付清单只指向当前最佳版，旧版可回退。
- [ ] 平台/接收端真实文件已核验；未核验的状态不写“已送达”。
