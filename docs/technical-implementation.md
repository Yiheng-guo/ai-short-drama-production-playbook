# 技术实现：让生成片段变成可控的连续剧

![镜头生产与验收流水线](../images/production-pipeline.svg)

本项目不是点一次“文生视频”得到整集。实际工作是：剧本固定人物行动和准确台词；生成平台提供候选镜头；本地用 **JSON 镜头清单 + FFmpeg** 做裁切、重排、混音、字幕和导出；人再按故事、视觉、声音、口型四项验收。真正难的不是让模型画出一张好看的脸，而是让不同片段在同一条时间线上保持**身份、声源、道具与动作状态**一致。

## 1. 数据结构：用镜头清单替代手工记忆

仓库提供本项目渲染器的整理版 [render_v2.py](../tools/render_v2.py) 和 [最小示例 manifest](../examples/episode-demo.json)。原片与角色参考不公开，因此示例可以执行 `--schema-only`；要真正渲染，需把 `raw/speaker.mp4`、`raw/listener.mp4` 换成自己的素材。

一个真实制作镜头在清单中至少有：

```json
{
  "id": "E5-05b",
  "source": "../raw/drama-ep05-E5-05-history2.mp4",
  "start": 7.7,
  "end": 9.5,
  "crop": {"x": 100, "y": 0, "width": 500, "height": 889},
  "source_audio": "mute",
  "note": "裁掉异常起音；另一条连续原声在整集时间线上对齐。"
}
```

这是第五集的**简化摘录**，不是可以独立播放的整集清单。`source` 指向不覆盖的原始生成片；`start/end` 决定采用秒段；`source_audio` 决定保留同期人声、只留环境声还是静音；`crop` 隔离错误文字或画面边缘。清单还记录可选画外 WAV 的入点、淡入淡出和电话滤波。任何镜头换源或改切点，都留下新候选版本，旧版可回退。

### 声源是显式状态

| `source_audio` | 适用画面 | 规则 |
|---|---|---|
| `native` | 说话人露脸、嘴可见 | 保留同镜原声；这时音画天然同源，仍需人耳听自然度。 |
| `ambient` | 无对白动作、听者反应 | 仅降低原片音量，不做声源分离；素材含可辨识的旧对白时应静音或换源。 |
| `mute` | 要另配电话/画外声或原声有错 | 完全停用源声；新增声必须标明谁说、从何处来、何时入画。 |

这项约束来自真实穿帮：第五集“你真去啊？”曾落到妈妈嘴上，第六集纸条句出现两层人声。若人物正面开口且新声无法对口型，优先换**同镜同期声**或改用听者/手部/背面镜，不能靠字幕把错声源藏过去。

## 2. 渲染器做了什么

`render_v2.py` 把每个镜头转为统一的 **720×1280、24 fps、48 kHz 音轨**。核心步骤是：

```text
逐镜校验时长与媒体流
  → trim / setpts（画面与声音用同一源区间）
  → crop / scale / fps（统一画幅和帧率）
  → 原声、环境声或静音三选一
  → concat（按镜头卡顺序拼接）
  → 可选 WAV 画外对白 + 电话 300–3400 Hz 频带
  → limiter / AAC + H.264 输出
  → 解码、时长、分辨率和切点黑帧检查
  → 校验通过后才把临时文件放到正式输出路径
```

电话滤波只负责空间听感，**不能修复说话人归属**。音量标准化可以压住突兀响度，**不能把机器念稿变成人类表演**。脚本会拒绝无音轨却声明 `native` 的镜头、结束时间超过源片的裁切、与 24 fps 不相容的时长和已存在的输出文件。只有通过整集机器校验，才进入人工审片。

```bash
python3 tools/render_v2.py examples/episode-demo.json --schema-only
python3 tools/render_v2.py examples/episode-demo.json --validate-only
python3 tools/render_v2.py examples/episode-demo.json
```

前一条只校验 JSON；后两条需要自己的媒体文件及 FFmpeg。脚本复用的是本项目实际使用的渲染逻辑，示例素材文件名是演示占位，不代表仓库含原片。

## 3. 质量门槛：机器可检与人必须看

| 关卡 | 机器能做 | 人必须做 | 失败后怎样处理 |
|---|---|---|---|
| 素材入库 | 文件、时长、分辨率、音轨存在性 | 角色是不是同一个人；手和道具是否变形 | 候选隔离，不进剪辑清单 |
| 对白 | ASR 提示重字/漏字；音频响度、声道检查 | 人味、情绪、角色声线、回应是否自然 | 重做该句；若露嘴，连画面一起重做或改镜 |
| 画面证据 | 当前人工核字；OCR 属于后续扩展 | 名单、票、纸条能否原速看懂 | 原片避开伪字，后期制作可控文字 |
| 镜头拼接 | 完整解码、总时长、内部切点黑帧 | 视线、方向、动作、道具状态和气口 | 回到对应镜头卡调整源秒段 |
| 整集/六集 | 文件批量校验与清单比对 | 首看能否讲出人物要做什么；钩子是否有因果 | 补行动/对白镜或重写前因 |

“自动检查通过”只说明文件技术上可播。它不能证明观众看得懂，也不能判断一个表情是否像同一位角色。因此我们采用**静音看 → 闭眼听 → 带声逐镜 → 六集连看**的人工验收顺序。问题记录精确到 `集数—成片时间—源镜头—错误—修复—复验`，避免“这集感觉怪”这种无法定位的反馈。

## 4. 返工路由：只改问题所在的层

- **故事断裂**：先查剧本的“目标→阻力→选择→结果”。预热片可以帮助首次进入，但第一集核心因果仍须自洽。
- **人物/道具穿帮**：检查角色主参考、场景平面和道具账本；源片若只有尾段穿帮，就裁安全秒段；关键剧情镜无可用段则重生。
- **声音机械**：先试听同一角色的连续对话。替换为通过试听的同期声或重做表演；响度和滤波只是后处理。
- **口型错位**：以可见嘴为硬约束；调整镜头类型或重新生成。只改音频通常会扩大问题。
- **字幕/纸面乱码**：生成阶段不依赖模型写准汉字；正式字幕跟最终音频走，剧情文字由后期图层控制。
- **切点卡顿**：检查前后动作状态与源片帧率。音画必须按同一时间段剪，不能只把声音挪开。

这些路由对应本项目发生过的双手机、单脚站姿、机械妈妈声、第五集说话人错位、第六集双层声等问题。详见[项目复盘](project-retrospective.md)和[制作 SOP](production-sop.md)。

## 5. 三个实际修复案例

### 说话人归属：第五集“你真去啊”

原镜头把女儿问句配到妈妈的正面画面。修复时重新生成女儿露脸、妈妈仅作肩部前景的同桌镜头，使用源片 **2.8–7.2 秒**；问句位于源片 **4.6–5.8 秒**。manifest 保留 `source_audio: native`，启用响度标准化，目标为 **−18 LUFS**；旧画外问句 WAV 停用。验收同时检查嘴部、声音身份和妈妈后续回答，确保对话关系成立。

### 重复人声：第六集纸条段

问题句“到海边记得吃早饭”由额外 WAV 与原声叠加。修复直接停用该叠加项，并将纸条画面采用区间 **0–2.8 秒、11–13 秒**的源声设为 `mute`。随后回到合格同期对白。`ambient` 只调低音量，无法去除旧对白，因此不能用于消除这类双层人声。

### 可读剧情证据：第一集手机名单

名单 UI 用 Pillow 绘制，四个时间关键帧记录屏幕四角位置，逐帧线性插值。每帧通过 NumPy 求解八个透视变换系数，将文字图层映射到手机屏幕；用原图的暖色肤色阈值生成手指遮罩，再以高斯模糊羽化边缘，避免名单覆盖手指。替换片输出为无声视频，在整集清单中沿用已审核的反应音频。该方法适合本次运动较小、屏幕边界可定位的镜头，更复杂的遮挡需要重新跟踪和制作遮罩。

## 6. 产品化时该怎样设计

如果要把这套方法做成工具，核心对象应是**镜头卡**，而不是一格自由提示词。每张卡关联角色参考、声线、道具起止状态、准确台词、嘴部可见性、候选版本和平台扣点。后续系统可校验主参考、声源归属和道具配置是否齐全；生成画面中的双手机仍需视觉审查。当前渲染器已执行媒体流、时长、解码和切点黑帧检查，字幕识别与画面语义检测属于后续扩展。

产品指标也应跟着“合格片段”走：候选通过率、每个合格镜头扣点、单个有效秒成本、返工原因分布、跨集一致性问题、未看剧本观众的理解断点。单看生成次数或出片速度，会把抽卡与返工成本藏起来。本项目能核算[制作期积分与资源替代成本](cost-accounting.md)，但还没有发布后的完播或追更数据，不能据此宣称观众效果已验证。
